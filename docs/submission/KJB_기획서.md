# 2026 금융 AI Challenge 기획서 (팀 KJB)

팀명: KJB
구성원 성명: 금민권(팀장), 최지우(팀원)

## 1. 서비스 명칭

DONN(돈): 부채 걱정을 덜어드리는 금융 AI Agent
- 한 줄 설명: 대출을 가진 개인에게 "지금 무엇부터 해야 하는지"를 계산 근거와 함께 말해 주는 부채 전문 생성형 AI 에이전트
- 구조 원칙: 판단은 계산이, 말은 AI가. 수치는 계산 엔진이 만들고 생성형 AI는 의도 파악과 설명 문장만 맡는다

## 2. 아이디어 기획 핵심내용(요약)

- 대상: 대출 2건 이상을 가진 개인. 앱 설치와 가입 없이 모바일 웹 주소 하나로 이용
- 핵심 구조: 상환표, 시나리오, 행동 규칙 10가지, 공시 상품 순위는 결정론 계산 엔진이 만들고, 생성형 AI는 (1) 질문에서 의도와 조건 추출, (2) 계산 결과를 설명하는 문장 작성만 담당. AI는 이용자의 개인 수치를 보지 않고 자리표만 받아 문장을 쓰며 숫자는 코드가 채운다(슬롯 필링)
- 기능 1, 부채 진단과 행동 카드: 비상금 부족, 최고금리 대출 추가 상환, 금리인하요구권 대상, 대환 후보, 만기 임박, 고금리 소액, 저축률, 원리금상환비율, 노후소득 충당률, 안전 모드(연체 신호 시 공적 상담 우선)
- 기능 2, 공시 비교: 금융감독원 금융상품한눈에와 공공데이터포털 공시 1,914건을 이용자 조건으로 계산해 익명 라벨(A은행 신용대출)로 순위를 보여주고, 모든 비교를 결정 기록과 재현 해시로 남긴다. 상품 실명과 판매 링크는 노출하지 않는 정보 제공 모드
- 기능 3, 보이는 대화형 에이전트: 답변 위에 생각 과정(질문 확인, 무엇이 필요한지 파악, 내 대출 살펴보기, 공시 자료 찾기, 설명 쓰기, 마지막 점검)이 실시간으로 뜨고, 오른쪽 리소스 패널에 답변에 쓰인 자료가 종류별로 표시된다. 답변 경로는 직접 답변, 내부 자료, 외부 검색 순
- 기능 4, 대화가 계산을 다시 돌린다: "금리 5% 이하만"처럼 조건만 말하면 직전 조건 위에 변경분만 반영해 재실행하고 이전 결과와의 차이를 보여준다. "매달 30만 원 더 갚으면?", "은퇴를 60세로 하면?" 같은 계산형 질문은 도구를 호출해 전후 수치로 답한다
- 기능 5, 소비 패턴과 생애주기: 거래내역 파일을 대화창에 첨부하면 브라우저에서 파싱해 카테고리, 정기 결제, 급증 지출을 분석하고 절감액을 최고금리 대출의 단축 개월과 절감 이자로 연결한다. 재무비율 5개와 생애 단계, 노후 시뮬레이션 3종을 같은 부채 데이터 위에서 계산한다
- 기능 6, 제도 안내: 금리인하요구권, 개인채무조정, 개인회생, 불법 추심 대응, 금융소비자 권리, 연금 제도 등 15편을 출처와 확인일과 함께 요약해 답하고, 내부 자료에 없으면 외부 검색 결과를 출처 표시와 함께 보여준다
- 안전장치: 상품 실명과 "추천" 표현 금지 필터, 면책과 AI 고지 상시 표시, 위기 신호가 있는 메시지는 AI 없이 공적 상담 창구 안내, 생성 문장은 숫자 근거, 금칙어, 권유 표현, 빈말 검증을 통과해야 화면에 표시
- 검증: 합성 페르소나 8명 × 골든 질문 82개 자동 검증(재현 해시 일치, 금칙어 0건, 안전 모드 동작), 테스트 417개 통과, 배포 주소에서 실제 운영

## 3. 문제 정의 및 제안 배경

문제
- 대출을 여러 건 가진 사람은 "어떤 빚부터, 얼마씩, 어떤 제도를 써서" 줄일지 통합된 답을 얻기 어렵다. 금융 앱은 자사 상품 안내와 판매에 맞춰져 있어 이용자의 부채 전체를 놓고 행동 순서를 계산해 주지 않는다
- 금리인하요구권, 대환, 채무조정, 금융소비자 권리 같은 제도는 존재하지만 요건과 절차를 알기 어렵고, 본인 상황에 적용했을 때의 효과(이자 얼마, 몇 개월 단축)를 숫자로 확인할 길이 없다
- 생성형 AI 챗봇은 숫자를 지어내거나 특정 상품을 권유할 위험 때문에 금융회사가 도입을 주저한다. 답변의 근거와 자료가 보이지 않으면 이용자도 믿기 어렵다
- 연체 위기에 있는 이용자에게 새 대출 안내는 오히려 해롭다. 위기를 감지해 공적 상담으로 먼저 연결하는 안전장치가 서비스 안에 있어야 한다

대상 고객과 채널
- 대상: 대출 2건 이상을 가진 20대에서 50대 개인. 특히 학자금, 마이너스통장, 카드론이 섞인 사회초년생, 고금리 소액대출을 쓰는 자영업자, 결혼과 주거 목표가 있는 30대, 은퇴 전환기의 50대. 이 유형을 합성 페르소나 8명으로 만들어 검증했다
- 채널: 모바일 웹. 주소 하나로 접속해 앱 설치와 가입 없이 바로 체험한다. 부채 상담은 창구 방문의 심리적 부담이 크고 필요한 시점이 야간과 주말인 경우가 많기 때문이다. 브라우저별 세션 격리로 여러 명이 동시에 써도 데이터가 섞이지 않는다

## 4. 서비스 컨셉 및 차별성

- 컨셉: 부채 걱정을 덜어드리는 금융 AI Agent. 이용자는 말로 묻고, 에이전트는 계산 엔진을 호출해 숫자를 만들고, 그 숫자를 근거로 다음 한 걸음을 문장으로 설명한다
- 차별성 1, 숫자 환각 원천 차단: AI 입력에는 숫자를 넣지 않고 범주형 사실과 자리표만 전달하며, 출력의 숫자는 코드가 채운다. 질문에 없는 숫자를 AI가 만들면 버리고, 설명 문장은 라벨 없는 숫자, 빈말, 권유 표현 검증을 통과해야 표시된다. 위기 응답과 안전 모드 카드는 AI를 쓰지 않는다
- 차별성 2, 규제 정합 설계: 상품 실명과 판매 링크 대신 익명 라벨과 금감원 공시 링크만 노출한다(판매, 중개, 자문이 아닌 정보 제공과 계산). "추천" 표현을 코드가 걸러내고 면책과 AI 고지를 항상 표시한다. 모든 비교는 결정 기록과 재현 해시로 남아 "왜 이 순서였는가"를 나중에 똑같이 재현할 수 있다
- 차별성 3, 보이는 에이전트: 답변 위에 생각 과정 카드가 실시간으로 뜨고, 리소스 패널에 답변에 쓰인 자료(내 정보, 계산 결과, 제도 문서와 확인일, 공시 자료, 외부 출처)가 종류별로 표시된다. 답변 경로는 직접 답변, 내부 자료, 외부 검색 순이며 내부에서 답을 찾지 못할 때만 외부로 나간다
- 차별성 4, 대화가 계산을 다시 돌린다: 조건만 말하면 직전 비교 조건 위에 변경분만 반영해 재실행하고, 이전 결과와의 차이(후보 수, 1순위, 총이자)를 함께 보여준다. 추가 상환, 일시 상환, 대환, 은퇴 시점 변경 같은 계산형 질문은 도구를 호출해 전후 수치로 답한다
- 차별성 5, 데이터 최소 수집: 거래내역 파일은 브라우저에서 파싱하고 서버에는 요약만 남긴다. 개인신용정보 파생 수치는 외부 AI로 보내지 않고, 질문은 개인정보 마스킹 후에만 전달한다
- 차별성 6, 소비와 생애주기를 부채에 연결: 정기 결제와 급증 지출에서 찾은 절감액이 최고금리 대출의 단축 개월과 절감 이자로 이어지고, 재무비율과 노후 시뮬레이션이 같은 부채 데이터 위에서 계산된다

## 5. 활용 데이터 및 생성형 AI 모델 적용 방안

데이터
- 금융감독원 금융상품한눈에 API: 은행과 저축은행의 신용대출, 주택담보대출, 전세자금대출, 예금, 적금 공시 978건. 신용점수 구간별 전월 평균금리 같은 공시 의미를 그대로 표시한다
- 공공데이터포털: 주택금융공사 디딤돌 금리, 서민금융진흥원 서민금융상품 기본정보와 대출상품한눈에 936건
- 규제 파라미터 레지스터: 금리인하요구권 기준, 중도상환수수료, 원리금상환비율 기준, 국민연금 개시 연령 등을 시행일, 출처, 확인 여부와 함께 관리하고 미확인 값은 화면에 "(확인 필요)"로 표시한다
- 제도 안내 문서 15편: 금리인하요구권, 개인채무조정, 개인회생, 불법 추심 대응, 금융소비자 권리, 국민연금, 퇴직연금, 연금저축 등. 찾기쉬운 생활법령정보, 금융감독원, 신용회복위원회 출처와 확인일을 기재한다
- 이용자 데이터: 부채, 소득, 지출, 자산, 목표(직접 입력 또는 합성 페르소나 8명), 거래내역 파일(CSV, XLSX)
- 수집과 활용: 공시는 스냅샷 단위로 적재하고 스냅샷 ID를 결정 기록에 남겨 재현한다. 이용자 데이터는 브라우저별 세션에 저장하고 원본 거래내역은 저장하지 않는다. 오픈뱅킹과 마이데이터 연동은 PoC에서는 구현하지 않았다

생성형 AI 모델
- 모델: Gemini Flash 계열. 응답 실패 시 다음 모델과 다음 키로 자동 전환하는 체인 구조이며, 실서비스에서는 엔터프라이즈급 API로 교체할 수 있는 어댑터 구조다
- 역할 1, 의도와 조건 추출: 질문을 개인정보 마스킹한 뒤 JSON 스키마(의도, 카테고리, 금액, 기간, 금리 상한, 제외 회사)로 추출한다. 질문에 없는 숫자는 코드가 폐기한다
- 역할 2, 설명 문장 생성(슬롯 필링): 계산 결과의 범주형 사실(익명 라벨, 정렬 기준, 절감 방향)과 자리표만 받아 문장을 쓰고 코드가 숫자를 채운다. 공시 비교 요약과 상위 3개 이유, 행동 카드 설명, 계산형 질의 결론에 쓰며 검증 실패 시 준비된 문장으로 대체한다
- 역할 3, 제도 문서 요약: 참조 문단만 입력해 요약 1문장과 핵심 3개를 쓰고, 문단에 없는 숫자가 나오면 규칙 렌더링으로 대체한다
- 역할 4, 직접 답변과 외부 검색: 인사와 도움말은 바로 답하고, 내부 자료에 없는 시점성 질문은 검색 그라운딩으로 답하며 출처를 표시한다(확인 필요 배지). 금융회사나 상품명이 섞이면 요약을 버리고 출처 링크만 남긴다
- AI가 하지 않는 것: 계산, 순위 결정, 상품 선택, 위기 응답. 위기 신호가 있는 메시지는 규칙으로 감지해 신용회복위원회, 서민금융콜센터, 자살예방상담전화 등 공적 창구를 안내한다
- 파이프라인: 질문 확인(마스킹, 위기 감지) → 무엇이 필요한지 파악(AI, 실패 시 규칙 파서) → 내부 노드(내 대출, 계산 엔진, 공시 자료, 제도 문서) → 설명 쓰기(AI 슬롯 필링) → 마지막 점검(금칙어, 권유 표현, 숫자 검증) → 답변. 모든 단계가 화면에 표시된다

## 6. 기대 효과 및 확장 가능성

해결하는 문제와 기대 효과
- 이용자는 "지금 무엇부터"를 숫자로 받는다. 추가 상환 시 단축 개월과 절감 이자, 대환 후보의 총이자 차이와 수수료 회수 기간, 비상금 부족액, 노후 부족액을 한 화면에서 확인한다
- 제도 접근성: 금리인하요구권, 채무조정, 금융소비자 권리를 본인 상황에 맞춰 안내하고 요건 확인 절차와 공식 창구로 연결한다
- 위기 예방: 연체 신호가 있으면 새 대출 대신 공적 상담을 먼저 안내하는 안전 모드가 항상 작동한다

금융 고객과 서비스 제공자의 실질적 혜택
- 고객: 이자와 시간을 아끼는 구체적 행동 순서, 제도 활용 가능성, 상담 창구 방문 전 준비 자료
- 제공자: 규제 준수형 생성형 AI 도입 모델(숫자 환각 차단, 추천 표현 필터, 감사 가능한 결정 기록, 사람 검수 게이트)을 그대로 가져갈 수 있고, 반복 상담(상환 순서, 대환 여부, 제도 문의)을 자동화해 상담 부담을 줄이며 정보 제공 모드에서 쌓은 신뢰를 제휴 모드로 이어갈 수 있다

시장 확대와 기능 확장
- 데이터: 오픈뱅킹과 마이데이터 연동으로 부채와 소득 입력 자동화, 월간 리포트와 넛지 알림
- 기능: 실명 상품 비교와 신청 연결(대출성 상품 중개 라이선스 확보 시), 가족 단위 재무설계, 자영업자와 소상공인 대출, 보험과 연금 상품군
- 채널: 은행 앱 내 위젯, 공공 상담기관(서민금융진흥원, 신용회복위원회)의 상담 보조 도구, 메신저 채널

타 영역 응용
- 계산 엔진과 가드레일은 도메인에 독립적이다. 공시 데이터와 규칙만 바꾸면 통신비, 구독, 공과금 최적화나 해외 대출 공시 비교로 확장할 수 있는 어댑터 구조다
