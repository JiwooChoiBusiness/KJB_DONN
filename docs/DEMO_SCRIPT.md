# DONN 데모 스크립트 (P6 마일스톤)

목적: PMO가 투자자/파트너 앞에서 5분 안에 6개 장면(docs/DONN_POC_SCOPE.md 1절)을
순서대로 보여줄 수 있도록 클릭 경로, 입력 문장, 기대 결과, 말할 포인트, 실패 시
대응을 정리한다. 숫자 예시는 전부 `docs/reports/latest.md`(페르소나 러너 리포트,
--llm rule 모드, data/donn.db 임시 복사본 기준)에서 실제로 확인한 값이다. 화면
문구는 web/app.js·web/index.html 현재 버전(작성일 2026-09-06) 기준이며, 화면이
계속 다듬어지고 있으므로 문구가 조금 달라 보이면 이 문서의 의도(어떤 화면, 어떤
조작)를 기준으로 진행한다.

사용자 서버 포트는 3666이다(`python run.py`). 데모는 항상 3666에서 진행한다
(3676은 Claude Code 테스트 전용).

## 사전 준비 체크리스트

1. **서버 실행**: 저장소 루트에서 `python run.py` 실행 후 `http://localhost:3666`
   접속. 콘솔에 오류 로그가 없는지 확인한다.
2. **데이터 적재 확인**: 브라우저나 `curl http://localhost:3666/api/health`로
   `snapshot_id`가 비어 있지 않은지 확인한다. 비어 있으면
   `run.bat load`(또는 `python -m scripts.load_products --source finlife --groups 020000,030300`
   다음 `python -m scripts.load_products --source datago`)를 먼저 실행한다.
   `GET /api/products/stats`의 `total_products`가 0보다 커야 장면 3의 공시 비교에
   후보가 나온다.
3. **Gemini 키 상태**: 같은 `GET /api/health` 응답의 `llm_available`을 확인한다.
   `true`면 채팅이 실제 Gemini 추출을 탈 수 있고(내부적으로 실패하면 규칙 파서로
   자동 전환), `false`면 처음부터 규칙 파서로만 동작한다. 어느 쪽이든 화면 동작은
   동일하게 보이므로 데모 자체는 키 없이도 안전하게 진행할 수 있다. 다만 발표
   중 "AI가 답한다"는 점을 보여주고 싶다면 사전에 `llm_available: true`인지
   확인해둔다.
4. **브라우저 새로고침**: 데모 직전에 강력 새로고침(Ctrl+Shift+R)으로 캐시된
   이전 화면을 지운다. `main.py`가 `/`와 `/static`에 `Cache-Control: no-cache`를
   붙이므로 평소에도 캐시 문제는 적지만, 발표 전에 한 번 더 확인한다.
5. 사이드바에서 이전 데모의 대화 기록이 남아 있으면 정리해도 되고, 그대로 둬도
   무방하다(페르소나별로 분리되어 표시된다).

## 5분 리허설 타임라인

| 시간 | 장면 | 핵심 동작 |
|---|---|---|
| 0:00~0:45 | 장면 1 첫 화면 | 계정 선택 전 상태, 면책·AI 고지, 칩 5개 |
| 0:45~1:30 | 장면 2 부채 입력 → 행동 카드 | P1(김서연) 계정 전환, 홈 카드 3장 |
| 1:30~2:30 | 장면 3 조건 확인 → M0 공시 비교 | 공시 비교 1단계 확인 → 2단계 결과 |
| 2:30~3:15 | 장면 4 후속 질의 재실행 | P2(박준호)로 전환, 채팅 두 번(조건 추가) |
| 3:15~4:00 | 장면 5 소비 패턴 | P3(이미라)로 전환, 합성 데이터 분석 |
| 4:00~5:00 | 장면 6 페르소나 러너 | 터미널에서 리포트 열기, 요약 표 설명 |

각 구간은 30초 여유를 포함한 목표치다. 질문이 들어오면 장면 6(재현성)을 가장
먼저 희생해도 된다(리포트는 이미 파일로 존재하므로 나중에 링크만 공유해도 된다).

## 장면 1: 첫 화면 (C안 하이브리드)

- **사용 계정(페르소나)**: 없음(계정 선택 전 온보딩 상태)
- **클릭 경로**: `http://localhost:3666` 접속(또는 새로고침). 아무것도 클릭하지
  않는다.
- **입력할 문장**: 없음(관찰만)
- **기대 결과**(러너 리포트 기준 실측치)
  - 인사이트 카드 2장: "부채를 등록하면 이렇게 계산돼요"(예시 금리 6.0%, 예시
    월 상환액 계산 예시 포함), "페르소나로 먼저 체험해볼 수 있어요"
  - 칩 5개: 페르소나로 체험하기 / 신용대출 공시 비교하기 / 주택담보대출 공시
    비교하기 / 전세자금대출 공시 비교하기 / 내 부채 직접 입력하기
  - 화면 하단에 면책 문구와 AI 고지 문구가 항상 보임(작은 글씨, 상시 노출)
  - `GET /api/home`의 `llm_calls`는 0(개발자 도구 Network 탭에서 확인 가능)
- **말할 포인트**: 첫 화면은 LLM을 한 번도 부르지 않고 뜬다. 순위와 숫자는 전부
  코드가 계산한 결과이고, 생성형 AI는 문장을 다듬는 역할만 한다는 이 제품의
  가장 중요한 규칙을 첫 화면에서부터 증명하는 장면이다.
- **실패 시 대응**: 카드가 안 보이면 `run.bat load`로 상품 스냅샷이 실제로
  적재됐는지 먼저 확인한다(카드 2장 중 두 번째 카드는 적재된 상품 수를 그대로
  보여주므로 0개면 문구가 어색해진다). 화면이 완전히 비어 있으면 콘솔에서 정적
  파일 404 여부를 확인한다.

## 장면 2: 부채 입력 → 행동 카드

- **사용 계정**: P1 김서연(29, 사회초년생 마케터, 서울 월세)
- **클릭 경로**: 상단바 오른쪽 아바타 클릭 → "계정 선택 (PoC)" 화면 → P1 카드의
  "이 계정으로 보기" 클릭 → 자동으로 홈으로 이동
- **입력할 문장**: 없음(계정 전환만으로 홈이 다시 계산된다)
- **기대 결과**(러너 리포트 실측치)
  - 홈 카드 3장:
    1. 행동(action) 카드 "비상금부터 채우세요": "비상금이 200,000원으로 생활비
       1개월분(1,750,000원)에 못 미칩니다. 1,550,000원을 먼저 모으는 방법을
       생각해보세요."(R4 규칙)
    2. 부채 요약 카드 "내 부채 한눈에 보기": "현재 등록된 대출 4건의 총잔액은
       19,800,000원이고, 이번 달 원리금 합계는 490,290원입니다."
    3. 목표 진행률 카드 "비상자금 목표 진행률": "목표 비상자금의 40% 확보
       (200,000원 / 500,000원)."
  - 칩 3개(상환표 보기 / 시나리오로 확인하기 / 공시 비교해보기)
- **말할 포인트**: 카드 문구의 모든 숫자(200,000원, 1,750,000원, 1,550,000원)는
  R0~R10 규칙 엔진이 대출 스케줄과 이번 달 여력을 계산해서 만든 값이다. 같은
  계정을 다시 불러오면 정확히 같은 문장과 숫자가 나온다(재현성). "왜 이 카드가
  나왔나요?" 토글을 눌러 규칙 근거 문장도 보여줄 수 있다.
- **실패 시 대응**: P1 대신 다른 계정이 보이면 계정 전환이 안 된 것이므로
  아바타를 다시 클릭해 계정 선택 화면으로 돌아간다. 카드가 3장이 아니면(1~3장
  범위 밖) 새로고침 후 재시도하고, 그래도 재현되면 하드 실패이므로 발표를
  중단하지 말고 장면 6의 러너 리포트로 넘어가 "리포트에 이미 잡혀 있다"고
  설명한다.

## 장면 3: 조건 확인 → M0 공시 비교

- **사용 계정**: P1(이어서 진행)
- **클릭 경로**: 사이드바 "리소스" 그룹의 "공시 비교" 클릭 → 1단계 "이 조건으로
  비교할까요?" 카드에서 추정된 항목(추정 배지) 확인 → 필요하면 금액/기간 수정 →
  "이 조건으로 비교" 클릭
- **입력할 문장**(채팅으로 진입하고 싶다면): "신용대출 500만원 12개월로 공시
  비교해줘"
- **기대 결과**(러너 리포트 실측치, 조건: 신용대출 500만원/12개월 기준)
  - 정렬 기준 문장: "대출금액 2,400,000원, 기간 12개월 기준으로 총이자가 적은
    순으로 정렬했습니다"(채팅 없이 화면에서 바로 들어가면 추정 대출 잔액
    2,400,000원 기준으로 조건이 잡힌다. 채팅으로 500만원을 명시하면 그 값으로
    조건이 바뀐다.)
  - 상위 10건(전체 후보 75건 중): 1위 "A은행 신용대출" 5.47%(전월 평균금리),
    2위 "B은행 신용대출" 5.56%, 3위 "C은행 신용대출" 5.66%. 실명·상호는 어디에도
    없다.
  - 가정 목록에 상품 스냅샷 ID, 공시 기준월(202608), 반올림 규칙, "공시된
    금리는 신청 시점의 공시 기준값이며 실제 승인 금리와 다를 수 있다"는 문구,
    추정한 필드 목록이 그대로 보인다.
  - 결과 하단에 decision_id와 result_hash가 작은 글씨로 보인다.
- **말할 포인트**: 이 화면 어디에도 은행 실명이 없다. 규제 등록 없는 M0
  단계에서는 익명 라벨과 금감원 공시 링크만 쓰고, 특정 상품을 권하는 말 대신
  비교 결과와 공시 열람 경로만 안내한다. 정렬 기준 한 줄과 가정 목록이 같이
  붙어 있어서 왜 이 순서인지 설명할 수 있다.
- **실패 시 대응**: 후보가 0건이면 상품 스냅샷 미적재 문제이니 장면 1의 체크리스트
  2번으로 돌아간다. "조건 바꿔서 다시 보기"로 1단계로 돌아가 금액을 바꿔서
  다시 시도해도 된다.

## 장면 4: 후속 질의 재실행

- **사용 계정**: P2 박준호(38, 맞벌이, 최근 승진)로 전환
- **클릭 경로**: 아바타 → 계정 선택 → P2 → "이 계정으로 보기" → 채팅 입력창에
  차례로 입력
- **입력할 문장 1**: "신용대출 3천만원 24개월로 공시 비교해줘"
- **입력할 문장 2**(같은 대화창에 이어서): "신용대출 3천만원 금리 4% 이하로
  비교해줘"
- **기대 결과**(러너 리포트/실측 로그 기준)
  - 1번째 응답: "신용대출 비교 조건을 준비했어요. 금액 30,000,000원, 기간
    24개월 기준입니다." → 공시 비교 결과 1위 "A은행 신용대출" 4.48%(전월 평균),
    월 1,309,166원, 총이자 1,419,995원.
  - 2번째 응답: "신용대출 비교 조건을 준비했어요. 금액 30,000,000원, 기간
    4개월 기준입니다."(금리 상한 4%가 새로 추가되고, 기간은 이번 발화에서
    말하지 않아 이 신용대출의 실제 잔여기간인 4개월로 다시 추정됐다)
- **말할 포인트**: 매 요청은 프로필의 실제 대출 조건을 기본값 삼아 새로
  계산된다. 이번 발화에서 말하지 않은 조건(이번 예시의 기간)은 대화 기억이
  아니라 프로필의 실제 값으로 다시 추정한다는 점을 투명하게 보여주는 것이
  포인트다. 금액처럼 매번 같은 값을 다시 말하면 그대로 유지되고, 조건 확인
  화면에는 어떤 값이 추정됐는지 배지로 표시된다. "AI가 맥락을 기억한다"고
  과장하지 않고 "조건을 다시 말하면 그 조건대로 다시 계산한다"고 설명한다.
- **실패 시 대응**: 두 번째 응답의 기간이 예상과 다르게 나와도 오류가 아니다.
  이 프로토타입은 대화 맥락을 이어받는 슬롯필링을 아직 구현하지 않았고(이후
  단계 범위), 매 발화가 프로필 기준으로 독립적으로 계산된다는 점을 사전에
  숙지해 자연스럽게 설명한다. 조건을 확실히 유지하고 싶다면 발화마다 금액과
  기간을 모두 말하도록 안내한다.

## 장면 5: 소비 패턴

- **사용 계정**: P3 이미라(45, 카페 운영 개인사업자, 부산)로 전환
- **클릭 경로**: 아바타 → 계정 선택 → P3 → "이 계정으로 보기" → 사이드바
  "소비 패턴" 클릭 → 합성 데이터로 분석(페르소나 합성 거래내역 3개월 사용)
- **입력할 문장**: 없음(화면에서 합성 데이터 분석 버튼 클릭)
- **기대 결과**(러너 리포트 실측치, 최근 3개월 합성 거래내역 기준)
  - 총 지출 6,112,965원, 월평균 2,037,655원. 고정지출 3,166,818원(52%),
    변동지출 1,153,061원, 재량지출 1,793,086원.
  - 카드 4장 예시: "지출이 늘어난 카테고리가 있어요"(의료 지출 전월 대비 증가),
    "이번 달 저축 여력"(약 462,345원), "고정지출 비율"(52%, 자영업자 특성상
    보증부 사업자대출·카드론·리볼빙 상환이 대출상환 카테고리로 잡힌다), "정기
    결제 현황"(6건, 월 합계 약 1,021,988원)
  - 상위 가맹점·구독 표시명은 앞 2자 + "**"로 마스킹되어 보인다(예:
    "보증**", "카드**").
- **말할 포인트**: 원본 거래내역은 서버에 저장되지 않는다. 분석은 사용자가
  파일을 올리거나 합성 데이터를 명시적으로 선택했을 때만 실행되고(자동 실행
  없음), 서버에는 집계된 요약·피처만 남는다. 자영업자인 P3는 고정지출 비율이
  52%로 이미 절반을 넘는데, 이 비율에는 대출 상환이 포함되어 있어 "돌려막기"
  구조가 숫자로 드러난다.
- **실패 시 대응**: 카드가 안 보이면 분석이 아직 실행되지 않은 것이므로 합성
  데이터 버튼을 다시 클릭한다. 숫자가 위와 다르면 실행 시점의 오늘 날짜 기준
  최근 3개월 창이 달라진 것이므로(합성 데이터는 seed=42로 고정되어 있지만
  기준일이 바뀌면 포함되는 달이 바뀐다) 당황하지 말고 "날짜 기준으로 매달
  갱신되는 창"이라고 설명한다.

## 장면 6: 페르소나 러너

- **사용 계정**: 8명 전원(화면이 아니라 터미널에서 실행하는 리포트)
- **클릭 경로**: 데모 전에 미리 실행해 두고, 발표 중에는 결과 파일만 연다.
  ```
  .venv\Scripts\python -m scripts.run_personas
  ```
  실행 후 `docs/reports/latest.md`를 열어 화면 공유한다.
- **입력할 문장**: 없음(CLI 실행)
- **기대 결과**(실제 리포트 값, LLM 모드 rule)
  - 골든 질문 66개(페르소나 8명 x 8~9문항), 하드 실패 0건, 소프트 경고 2건
  - 페르소나별 result_hash가 1차/2차 실행에서 완전히 일치(재현성 100%),
    `POST /api/decisions/{id}/replay`도 8명 전원 일치(match=true)
  - 소프트 경고 2건은 모두 P5·정수민, P7·한도윤의 위기 표현("추심 전화 받기가
    너무 무서워요", "죽고 싶어요")에 대한 것으로, 홈 화면의 안전 모드(R0)
    카드는 정확히 유지되지만 채팅 응답 자체에 위기상담 채널을 우선 안내하는
    전용 분기가 아직 없다는 발견 사항이다(PMO 검토 필요, app/ 코드는 이번
    작업 범위에서 건드리지 않았다).
  - 부가 발견: 연체 신호 플래그가 없는 P2(박준호)·P3(이미라)·P8(한소희)도
    실제 계산 결과 원리금상환비율이 55~94%, 이번 달 남는 돈이 음수로 나와
    안전 모드(R0) 카드가 뜬다. 자기 신고가 아니라 계산만으로 위험을 판정하는
    구조라는 근거로 쓸 수 있다.
- **말할 포인트**: "같은 조건이면 같은 결과"가 이 제품의 핵심 규제 원칙이다.
  페르소나 8명을 상환표·시나리오·생애주기·소비 패턴·공시 비교·결정 재현·
  채팅까지 전 구간에서 자동으로 돌려도 결과가 항상 재현되고, 상품명·회사명·
  em dash 같은 금지 표현이 하나도 새어나오지 않는다는 것을 이 리포트 한 장으로
  증명한다. 안전 모드는 사용자가 스스로 "위험하다"고 말하지 않아도 숫자만으로
  작동한다는 점도 함께 강조한다.
- **실패 시 대응**: 하드 실패가 있으면 리포트의 "실패 목록 (하드)" 표를 그대로
  화면 공유하고 어느 페르소나·어느 검사인지 짚어준다(발표를 멈추지 않는다).
  Gemini 키 상태에 따라 `--llm live`로 실행한 리포트는 지연시간이 초 단위로
  늘어날 수 있으니, 발표 중에는 항상 기본값인 `--llm rule` 리포트를 보여준다.
