# DONN 데모 스크립트

목적: PMO가 투자자/파트너 앞에서 6분 안에 6개 장면(docs/DONN_POC_SCOPE.md 1절)을
순서대로 보여줄 수 있도록 클릭 경로, 입력 문장, 기대 결과, 말할 포인트, 실패 시
대응을 정리한다. 숫자 예시는 `docs/reports/latest.md`(페르소나 러너 리포트,
--llm rule 모드, 2026-09-06 11:08 생성, data/donn.db 임시 복사본 기준)와 화면
코드(web/app.js, app/api/routes.py) 확인으로 검증한 값이다. 화면 문구는 이 문서
작성 시점(2026-09-06, 대화 화면·답변 경로 반영 이후)의 web/app.js·web/index.html
기준이며, 화면이 계속 다듬어지고 있으므로 문구가 조금 달라 보이면 이 문서의
의도(어떤 화면, 어떤 조작)를 기준으로 진행한다.

데모는 배포 주소를 우선으로 진행한다. 로컬(`python run.py`, http://localhost:3666)은
네트워크 문제가 생겼을 때 쓰는 예비 경로다. Claude Code의 테스트·미리보기 전용
포트(3676)는 데모에 쓰지 않는다.

## 사전 준비 체크리스트

1. **배포 주소를 발표 10분 전에 미리 깨워둔다.** Render 무료 플랜은 15분 무접속
   시 절전 상태가 되고 첫 접속에 30초~1분이 걸린다. 발표 직전이 아니라 미리
   `https://kjb-donn.onrender.com`에 접속해 절전을 풀어 둔다. GitHub
   Pages(`https://jiwoochoibusiness.github.io/KJB_DONN/`)는 정적 호스팅이라
   README 랜딩만 보여주고 앱은 실행되지 않으므로 데모 화면으로 쓰지 않는다.
2. **상태 확인**: 배포 주소에서 `GET /api/health`를 열어(브라우저 주소창에
   `https://kjb-donn.onrender.com/api/health`) `snapshot_id`가 비어 있지 않은지
   확인한다. 공시 시드 데이터(`seed/products_seed.json.gz`, 금감원 978건 + 공공
   데이터 936건 = 1,914건, 2026년 8월 공시 기준)가 시작 시 자동으로 적재되므로
   보통은 문제가 없지만, 혹시 비어 있으면 새로고침 후 다시 확인한다.
3. **Gemini 키 상태와 한도 소진 대응**: 같은 `GET /api/health` 응답의
   `llm_available`을 확인한다. `true`여도 무료 티어 한도(429)에 걸리면 자동으로
   규칙 기반 응답으로 전환되며, 오늘 실제로 한도가 소진된 상태에서 이 폴백이
   정상 동작하는 것을 확인했다. 즉 발표 중 배지가 "AI 응답" 대신 "규칙 기반
   응답"으로 보여도 오류가 아니라 설계된 동작이다. 이 점을 미리 알아두면
   당황하지 않는다.
4. **로컬 예비 서버**: 저장소 루트에서 `python run.py` 실행 후
   `http://localhost:3666`으로 켜 둔다. 배포 주소가 응답하지 않을 때만 이쪽으로
   전환한다.
5. **브라우저 새로고침**: 데모 직전에 강력 새로고침(Ctrl+Shift+R)으로 캐시된
   이전 화면을 지운다.
6. 사이드바에서 이전 데모의 대화 기록이 남아 있으면 정리해도 되고, 그대로 둬도
   무방하다(페르소나별로 분리되어 표시된다).

상세 배포 구성(Render 블루프린트, 환경변수, Pages 랜딩 구성)은 `docs/DEPLOY.md`에
정리되어 있다.

| 시간 | 장면 | 핵심 동작 |
|---|---|---|
| 0:00~0:40 | 장면 1 첫 화면 | 계정 선택 전 상태, 면책·AI 고지, 칩 5개, LLM 0회 |
| 0:40~1:25 | 장면 2 부채 입력 → 행동 카드 | P1(김서연) 계정 전환, 홈 카드 3장, "AI 설명 보기" |

| 2:50~4:20 | 장면 4 후속 질의와 답변 경로 | P2(박준호)로 전환, 조건 변경·제도 안내·direct·external, 리소스 패널 |
| 4:20~5:10 | 장면 5 소비 패턴 | P3(이미라)로 전환, 합성 데이터 분석 |
| 5:10~6:00 | 장면 6 페르소나 러너 | 터미널에서 리포트 열기, 요약 표 설명 |

각 구간은 여유를 포함한 목표치다. 질문이 들어오면 장면 6(재현성)을 가장 먼저
희생해도 된다(리포트는 이미 파일로 존재하므로 나중에 링크만 공유해도 된다). 장면
4가 길어지면 direct·external 시연 중 하나만 보여줘도 된다.

## 장면 1: 첫 화면 (C안 하이브리드)

- **사용 계정(페르소나)**: 없음(계정 선택 전 온보딩 상태)
- **클릭 경로**: 배포 주소 접속(또는 새로고침). 아무것도 클릭하지 않는다.
- **입력할 문장**: 없음(관찰만)
- **기대 결과**
  - 상단 바 로고 "DONN" 옆에 작은 "PoC" 표시. 브라우저 탭 제목은 "DONN 부채
    전문 AI Agent".
  - 중앙 큰 제목 "DONN"과 부제 "부채 걱정을 덜어드리는 금융 AI Agent".
  - 인사이트 카드 2장: "부채를 등록하면 이렇게 계산돼요"(예시 금리 6.0%, 예시
    월 상환액 계산 예시 포함), "페르소나로 먼저 체험해볼 수 있어요"
  - 칩 5개: 페르소나로 체험하기 / 신용대출 공시 비교하기 / 주택담보대출 공시
    비교하기 / 전세자금대출 공시 비교하기 / 내 부채 직접 입력하기
  - 화면 하단에 면책 문구와 AI 고지 문구가 항상 보임(작은 글씨, 상시 노출)
  - `GET /api/home`의 `llm_calls`는 0(개발자 도구 Network 탭에서 확인 가능)
- **말할 포인트**: 화면 이름은 "DONN 부채 전문 AI Agent"이고, 로고 옆에는 아직
  데모 단계임을 뜻하는 "PoC" 표시만 남겨뒀다. 이 첫 화면은 LLM을 한 번도 부르지
  않고 뜬다. 순위와 숫자는 전부 코드가 계산한 결과이고, 생성형 AI는 문장을
  다듬는 역할만 한다는 이 제품의 가장 중요한 규칙을 첫 화면에서부터 증명하는
  장면이다.
- **실패 시 대응**: 배포 주소가 절전 상태였다면 첫 응답이 30초~1분 걸릴 수
  있으니 침착하게 기다린다. 카드가 안 보이면 공시 시드 데이터가 자동 적재됐는지
  `/api/products/stats`로 확인한다(카드 2장 중 두 번째 카드는 적재된 상품 수를
  그대로 보여주므로 0개면 문구가 어색해진다). 화면이 완전히 비어 있으면 콘솔에서
  정적 파일 404 여부를 확인한다.

## 장면 2: 부채 입력 → 행동 카드

- **사용 계정**: P1 김서연(29, 사회초년생 마케터, 서울 월세)
- **클릭 경로**: 상단바 오른쪽 아바타 클릭 → "계정 선택 (PoC)" 화면 → P1 카드의
  "이 계정으로 보기" 클릭 → 자동으로 홈으로 이동
- **입력할 문장**: 없음(계정 전환만으로 홈이 다시 계산된다)
- **기대 결과**
  - 홈 카드 3장:
    1. 행동(action) 카드 "비상금부터 채우세요": "비상금이 200,000원으로 생활비
       1개월분(1,750,000원)에 못 미칩니다. 1,550,000원을 먼저 모으는 방법을
       생각해보세요."(R4 규칙)
    2. 부채 요약 카드 "내 부채 한눈에 보기": "현재 등록된 대출 4건의 총잔액은
       19,800,000원이고, 이번 달 원리금 합계는 490,290원입니다."
    3. 목표 진행률 카드 "비상자금 목표 진행률": "목표 비상자금의 40% 확보
       (200,000원 / 500,000원)."
  - 칩 3개(상환표 보기 / 시나리오로 확인하기 / 공시 비교해보기)
  - 행동 카드 하단에 "AI 설명 보기" 버튼이 있다.
- **시연 동작**: 행동 카드의 "AI 설명 보기" 버튼을 누른다. 누르는 순간에만
  `POST /api/actions/{action_id}/explain`이 호출되고(첫 화면 로드에서는 절대
  호출되지 않는다), "AI가 계산 결과를 읽고 설명을 쓰는 중이에요" 자리표시가 잠깐
  보인 뒤 문장이 채워지며 "AI 응답"(모델명 표시) 또는 "규칙 기반 설명" 배지가
  붙는다.
- **말할 포인트**: 카드 문구의 모든 숫자(200,000원, 1,750,000원, 1,550,000원)는
  R0~R10 규칙 엔진이 대출 스케줄과 이번 달 여력을 계산해서 만든 값이다. 같은
  계정을 다시 불러오면 정확히 같은 문장과 숫자가 나온다(재현성). "AI 설명
  보기"는 클릭했을 때만 LLM을 부르므로 "첫 화면 LLM 0회" 원칙이 여전히
  지켜진다는 점, 그리고 그 설명조차 LLM이 숫자를 직접 보거나 쓰지 않고 코드가
  채운 값이라는 점("LLM은 숫자를 보지 않는다")을 이 장면에서 짚어준다. "이 분석은
  왜 나왔나요?" 토글로 규칙 근거 문장도 보여줄 수 있다.
- **실패 시 대응**: P1 대신 다른 계정이 보이면 계정 전환이 안 된 것이므로
  아바타를 다시 클릭해 계정 선택 화면으로 돌아간다. 카드가 3장이 아니면(1~3장
  범위 밖) 새로고침 후 재시도하고, 그래도 재현되면 하드 실패이므로 발표를
  중단하지 말고 장면 6의 러너 리포트로 넘어가 "리포트에 이미 잡혀 있다"고
  설명한다. "AI 설명 보기"가 실패하면 "설명을 불러오지 못했어요"라는 문구만
  뜨고 나머지 화면은 그대로이므로 자연스럽게 넘어간다.

## 장면 3: 채팅으로 조건 확인 → M0 공시 비교

- **사용 계정**: P1(이어서 진행)
- **클릭 경로**: 홈 하단 입력창에 문장을 입력하고 전송 → 화면이 자동으로 대화
  화면(`#chat`)으로 전환된다(홈 자체는 그대로 유지되어 "첫 화면 LLM 0회" 원칙은
  깨지지 않는다) → 답변 위에 "생각 과정" 노드 카드 묶음이 실시간으로 채워진다
  (발화 점검 → 의도·조건 추출 → 계산 엔진 → 설명 작성 → 응답 점검, 총 5단계) →
  응답이 끝나면 카드 묶음이 "생각 과정 5단계 · 8.9초 · Gemini gemini-3.7-flash"
  같은 한 줄로 접히고, 답변 문장이 타자 효과로 나타난다 → 답변 아래 인라인
  액션 카드의 "조건 확인하고 비교하기" 버튼을 클릭한다 → 공시 비교 1단계 "이
  조건으로 비교할까요?" 카드에서 추정된 항목(추정 배지) 확인 → 필요하면
  금액/기간 수정 → "이 조건으로 비교" 클릭 → 2단계 결과.
  (참고: 사이드바 "리소스" 그룹의 "공시 비교"로 바로 들어가면 채팅과 생각 과정
  단계 없이 1단계 카드로 바로 간다. 오늘 데모는 채팅 흐름을 보여주는 것이
  목적이므로 위 경로를 권장한다.)
- **입력할 문장**: "신용대출 500만원 12개월로 공시 비교해줘"
- **기대 결과**
  - 생각 과정 카드 예시 문구: "발화 점검 · 개인정보 마스킹 완료" / "의도·조건
    추출 · Gemini {모델}, {ms}ms, 의도: 공시 비교"(LLM이 응답하지 않으면 "규칙
    파서로 대체") / "계산 엔진 · 비교 조건 준비: 신용대출, 금액 5,000,000원,
    기간 12개월(추정 N개)" / "설명 작성 · Gemini {모델}, {ms}ms"(또는 "템플릿
    문장 사용") / "응답 점검 · 상품명·회사명·권유 표현 없음 확인".
  - 답변 문장 끝에 "아래 버튼으로 조건을 확인하고 실행해보세요."가 코드로
    붙는다.
  - 정렬 기준 문장: "대출금액 2,400,000원, 기간 12개월 기준으로 총이자가 적은
    순으로 정렬했습니다"(채팅으로 500만원을 명시했으므로 그 값 기준으로 조건이
    잡힌다. 채팅 없이 화면에서 바로 들어가면 추정 대출 잔액 2,400,000원 기준으로
    조건이 잡힌다.)
  - 상위 10건(전체 후보 75건 중): 1위 "A은행 신용대출" 5.47%(전월 평균금리),
    2위 "B은행 신용대출" 5.56%, 3위 "C은행 신용대출" 5.66%. 실명·상호는 어디에도
    없다.
  - 가정 목록에 상품 스냅샷 ID, 공시 기준월(202608), 반올림 규칙, "공시된
    금리는 신청 시점의 공시 기준값이며 실제 승인 금리와 다를 수 있다"는 문구,
    추정한 필드 목록이 그대로 보인다.
  - 결과 하단에 decision_id와 result_hash가 작은 글씨로 보인다.
  - 결과 아래 "왜 이 순서인가요?" 블록: "AI가 계산 결과를 읽고 설명을 쓰는
    중이에요" 자리표시 후 실측 8~12초 안에(gemini-3.8-flash 또는
    gemini-3.7-flash) 요약 2~3문장과 상위 3개 항목의 이유 한 줄씩이 채워진다.
    검증 실패나 LLM 불가 시에는 조용히 템플릿 문장과 "규칙 기반 설명" 배지로
    바뀐다.
- **말할 포인트**: "수치는 코드가, 문장은 LLM이 쓴다"는 원칙을 생각 과정 카드로
  실시간으로 보여줄 수 있다. "왜 이 순서인가요?" 설명도 마찬가지로, LLM은 금리나
  금액 숫자를 직접 보지도 쓰지도 않는다. 코드가 빈칸(플레이스홀더)이 있는
  문장만 LLM에 요청하고, 검증을 통과한 문장에 코드가 숫자를 채운다("LLM은
  숫자를 보지 않는다"). 이 화면 어디에도 은행 실명이 없다. 규제 등록 없는 M0
  단계에서는 익명 라벨과 금감원 공시 링크만 쓰고, 특정 상품을 권하는 말 대신
  비교 결과와 공시 열람 경로만 안내한다.
- **실패 시 대응**: 후보가 0건이면 상품 스냅샷 미적재 문제이니 장면 1의
  체크리스트 2번으로 돌아간다. 스트림이 중간에 끊기면 화면이 자동으로
  `POST /api/chat`(생각 과정 없이 한 번에 응답)으로 재시도하므로 발표를 멈추지
  않아도 된다. "조건 바꿔서 다시 보기"로 1단계로 돌아가 금액을 바꿔서 다시
  시도해도 된다.

## 장면 4: 후속 질의와 답변 경로

- **사용 계정**: P2 박준호(38, 맞벌이, 최근 승진)로 전환
- **클릭 경로**: 아바타 → 계정 선택 → P2 → "이 계정으로 보기" → 대화 화면
  입력창에 차례로 입력한다(같은 대화창에 이어서 보낸다)
- **채팅 1**: "신용대출 3천만원 24개월로 공시 비교해줘"
  - 대화 화면 전환 → 생각 과정 5단계 → "신용대출 비교 조건을 준비했어요. 금액
    30,000,000원, 기간 24개월 기준입니다." → "조건 확인하고 비교하기" 클릭 →
    공시 비교 결과 1위 "A은행 신용대출" 4.48%(전월 평균), 월 1,309,166원,
    총이자 1,419,995원.
- **채팅 2(후속 질의)**: "신용대출 3천만원 금리 4% 이하로 비교해줘"
  - 생각 과정의 "계산 엔진" 카드가 "이전 조건에서 금리 상한만 변경"처럼
    바뀐 항목만 짚어준다. 응답: "신용대출 비교 조건을 준비했어요. 금액
    30,000,000원, 기간 4개월 기준입니다."(금리 상한 4%가 새로 추가되고, 기간은
    이번 발화에서 말하지 않아 이 신용대출의 실제 잔여기간인 4개월로 다시
    추정됐다)
- **채팅 3(제도 안내 질문)**: "중도상환수수료가 면제되는 조건이 있어?"
  - 이 질문은 내부(internal) 경로로 가고, 생각 과정에 "제도 안내" 노드가
    추가된다("제도 문서 1편에서 N개 문단을 참조했어요"). 답변은 KB 문서 본문을
    그대로 붙여넣지 않고 "한 줄 요약 → 핵심 3개(굵은 소제목) → 출처(문서명,
    확인일)" 형식의 카드로 정리되어 나온다. 오른쪽 리소스 패널의 "제도 안내"
    묶음에 문서가 추가된다.
- **direct 시연**: "안녕, DONN이 뭘 도와줄 수 있어?"
  - 자료가 필요 없는 질문이라 direct 경로로 바로 간다(생각 과정이 발화 점검 →
    직접 답변 → 응답 점검 4단계로 짧아진다). 개인 수치나 상품명 없이 "부채
    상환표, 공시 비교, 시나리오, 행동 제안, 제도 안내 중 무엇이든 물어보세요"
    같은 짧은 안내로 답한다.
- **external 시연**: "요즘 기준금리 얼마야?"
  - 내부 자료로 답할 수 없는 시점성 질문이라 external 경로로 넘어간다. Gemini의
    Google 검색 그라운딩으로 답을 만들고 "외부 검색 요약(확인 필요)" 배지와
    함께 웹 출처 링크가 리소스 패널의 "외부 출처" 묶음에 붙는다. 그라운딩이
    막혀 있거나 상품명·회사명이 섞여 나오면 요약 대신 공식 기관 안내 링크만
    보여준다.
- **리소스 패널**: 대화 화면 오른쪽(또는 1024px 미만에서는 답변 아래 접이식)의
  "리소스" 패널이 지금까지 쌓인 자료를 내 정보 / 계산 결과 / 제도 안내 / 공시
  자료 / 기준값 / 외부 출처로 묶어 개수와 함께 보여준다. 이번 장면을 진행하며
  이 패널에 항목이 하나씩 늘어나는 것을 보여준다.
- **말할 포인트**: 매 요청은 프로필의 실제 대출 조건을 기본값 삼아 새로
  계산된다. 이번 발화에서 말하지 않은 조건(이번 예시의 기간)은 대화 기억이
  아니라 프로필의 실제 값으로 다시 추정한다는 점을 투명하게 보여주는 것이
  포인트다. "AI가 맥락을 기억한다"고 과장하지 않고 "조건을 다시 말하면 그
  조건대로 다시 계산한다"고 설명한다. 그리고 질문의 성격(인사, 내 자료·제도
  질문, 시점성 질문)에 따라 direct·internal·external 세 경로 중 하나로 코드가
  자동으로 판정한다는 것, 제도 답변이 KB 문서를 그대로 쏟아내지 않고 요약 +
  핵심 + 출처로 정리된다는 것을 함께 짚어준다.
- **실패 시 대응**: 두 번째 응답의 기간이 예상과 다르게 나와도 오류가 아니다.
  이 프로토타입은 대화 맥락을 이어받는 슬롯필링을 조건 값 자체에는 아직
  전면적으로 적용하지 않았고, 매 발화가 프로필 기준으로 다시 계산된다는 점을
  사전에 숙지해 자연스럽게 설명한다. external 시연에서 그라운딩이 막혀 공식
  링크만 나와도 "이것이 설계된 폴백"이라고 설명하면 된다. 시간이 부족하면
  direct·external 중 하나만 보여줘도 된다.
