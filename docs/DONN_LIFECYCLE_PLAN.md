# DONN 생애주기 층(P7) 반영 계획

작성일 2026-09-06. 근거 문서: `docs/reference/lifecycle_domain_v1.txt` (PMO 제공 "소비패턴 기반 생애주기 재무설계 AI Agent 도메인 지식 문서 v1.0"). 이 문서는 DONN의 부채 코어 위에 생애주기 재무설계 층을 얹는 방법을 정한다. 기존 규칙(수치는 코드, M0 모드, 상품 실명 금지, 자문 경계)은 그대로 적용한다.

## 0. 한 줄 요약

도메인 문서의 6단계 프로세스, 5개 재무비율, 생애주기 7단계 실행표, 연금·노후 산식, 소비패턴 기반 이벤트 감지는 모두 DONN 구조에 그대로 들어간다. 다만 문서의 "상품 추천"은 DONN에서 "참고 시나리오와 행동 카드"로 바꾼다. 문서 6절도 "추천이 아닌 참고 시나리오" 문구를 권장하므로 방향이 같다.

## 1. 문서 항목과 DONN 구성요소 대응

## 2. 규제·표현 경계 (그대로 유지)

- 문서의 "IRP 추가납입 검토", "대환대출 상품 추천", "주택자금 마련 상품" 같은 문구는 DONN에서 상품 지목 없이 "노후자금 시뮬레이션 보기", "내 조건으로 공시 비교", "주거 자금 시나리오"로 바꾼다.
- 계좌 역할(연금계좌는 장기, ISA는 중기, 일반계좌는 유동성)은 제도 일반론이므로 교육 문구로 허용한다. 특정 상품·회사 언급은 금지.
- 자산배분 비중과 인출률은 "참고 모델"과 "시나리오 예시"로만 표시하고, 개인에게 "이 비중으로 하세요"라고 말하지 않는다.
- 연금·세제 수치(보험료율 9.5%, 소득대체율 43%, 세액공제 한도 900만 원, ISA 한도 등)는 `policy_params.yaml`에 시행일·출처·확인 필요 플래그로 두고 화면에 "(확인 필요)" 배지를 붙인다. 문서 자체가 ISA 개편안은 확정 법률이 아니라고 적고 있다.
- 자산·연금 수치는 G3 등급이다. 외부 LLM으로 보내지 않는다.

## 3. 구현 단위

### P7a 데이터 (builder, Sonnet)
- `app/models.py`: `Assets{liquid, investment, pension: {national_pension_months_paid, db_dc_balance, irp_pension_savings_balance, isa_balance}, real_estate}`, `Goal{kind, target_amount, target_date, priority}`, `UserProfile.assets/goals/dependents/risk_tolerance/income_type/life_stage_override`.
- 페르소나 8명에 자산·연금·부양가족·목표를 추가(문서 2.3 단계와 일치하도록 P1 사회초년기 … P6 은퇴준비기).
- `config/thresholds.yaml`: 생애 단계별 최소 유동성 개월(예: 사회초년기 3, 은퇴전환기 6), 최소 저축률(10~20%), 최대 원리금상환비율(40%), 노후소득 충당률 60%(50대 이상). 문서 값은 예시이므로 전부 needs_verification.

### P7b 코어 (builder, Sonnet)
- `ratios.py`: 5개 비율, 총자산·순자산, 각 비율의 해석 문장(상품명 없음).
- `lifecycle.py`: 단계 판정(7단계)과 근거, 단계별 우선순위·피해야 할 행동 콘텐츠.
- `retirement.py`: `fv`, `pv`, `annuity_pv`, `required_monthly_saving`, `real_rate`, `real_value`, `retirement_living_cost`, `retirement_gap`, `coverage_ratio`, `withdrawal_rate`, `rebalance_amounts`. 골든 벡터: 월 부족액 150만·25년·실질 3% → 약 3억 1,600만; 월 50만·30년·5% → 약 4억 1,600만; 목표 4억·20년·5% → 월 약 97만; 명목 5%·물가 2% → 실질 약 2.94%; 월 300만·물가 2%·20년 → 약 446만; 필수지출 250만·지속소득 180만 → 충당률 72%.
- `rules.py`: R7 유동성(비상자금 3개월 기준, 기존 R4 흡수), R8 저축률, R9 원리금상환비율 40%(M0 비교 안내), R10 노후소득 충당률(50대 이상, 시뮬레이션 안내). 생애 단계별 임계값 사용.
- `scenarios.py`: 생애 이벤트(결혼·출산·주택·은퇴)를 현금흐름 충격으로 반영하고 시야를 은퇴 시점까지 확장. 낙관·기준·비관 명칭을 문서와 맞춘다.

### P7c 화면 (web-designer, Opus)
- "생애 흐름" 화면: 재무비율 5개 게이지(단계별 임계값 표시), 생애 단계와 우선순위 카드, 노후자금 부족액 시뮬레이션(낙관·기준·비관), 50대 이상은 소득공백 지도, 순자산·부채 곡선. 모든 수치 옆에 가정 표시.
- 홈 카드: 목표 달성 진행률 프레이밍("목표 비상자금의 62% 확보").

### P7d 채팅·KB
- 의도 추가: retirement(노후·연금), saving(저축률·자동이체), liquidity(비상자금) → 해당 카드·화면.
- KB 문서 3편 추가: 국민연금 예상연금 확인 방법, 퇴직연금 DB·DC·IRP 개요, 연금저축·ISA 세제 개요(확인 필요 표시).

### P5 연계
- 이벤트 감지 규칙: 예식 관련 결제 증가 → 결혼 예정, 산부인과·유아용품 → 출산, 급여 입금 중단 → 이직·휴직, 대출 만기 임박 + 신용 상승 → 대환 여력. 감지 결과는 카드로만 제시하고 상품을 지목하지 않는다.

## 4. 순서 제안

현재 진행 순서(화면 수정 2차 → KB 연결 → P5 소비패턴 → P6 페르소나 러너 → 검토 게이트)에서 P7을 P5 다음, P6 앞에 넣는다. 페르소나 러너가 생애주기 질문까지 검사해야 하고, 대회 심사가 산식의 구조적 정확성을 본다면 노후·연금 산식의 골든 벡터 테스트가 먼저 있어야 하기 때문이다.
